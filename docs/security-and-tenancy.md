# 安全与租户隔离

## 身份认证

- Access Token 使用短时 JWT，由 `Authorization: Bearer` 传递。
- Refresh Token 通过 HttpOnly Cookie 保存，支持轮换、撤销和重放检测。
- 生产环境必须设置高强度 `JWT_SECRET`、HTTPS、`COOKIE_SECURE=true` 和明确的 CORS 来源。
- 登录与令牌接口启用限流；密码只保存强哈希。

## Tenant 隔离

当前用户的 Tenant 来自经过验证的身份上下文，不接受请求体传入的 Tenant ID。Repository 查询、唯一约束和关键外键均包含 `tenant_id`，防止仅靠控制器过滤。

普通用户只能访问自己的 Tenant。管理员是无 Tenant 的账号管理身份，只能管理 Tenant、账号、个人资料并查看管理员审计日志；不能调用订单、商品、库存、展会或报表 API。管理员操作使用单独端点并写审计日志。

跨 Tenant 访问应表现为资源不存在，避免泄露 ID 是否有效。所有新增业务查询都必须覆盖以下测试：

- Tenant A 不能读取、修改或删除 Tenant B 的交易、商品、展会和库存流水。
- Tenant A 不能把 Tenant B 的展会或商品 ID 写入自己的请求。
- 商品图片签名上传、预览和删除前重新验证商品归属。

## 输入与业务校验

- 交易金额必须为正数，每批最多 100 笔；批量删除最多选择 100 笔，且必须全部属于当前 Tenant，否则整批回滚。
- 展会必须属于当前 Tenant，交易日期必须位于展会范围内。
- 商品销量数量必须为正，重复商品先聚合，库存不足整批回滚。
- 搜索、分页、日期范围和上传图片大小均设置服务端上限。
- API 错误使用稳定错误码，不向客户端返回堆栈或 SQL 信息。

## 商品图片

文件能力仅用于商品图片。允许的图片类型和大小由后端校验；对象 key 由服务端使用 Tenant slug、编码后的商品 SKU 和随机 ID 生成，客户端不能指定任意路径。生产 Bucket 保持私有，原图只允许短期预签名上传，不提供下载 URL。商品页面只加载最长边 480 px 的低清预览，并通过带 Tenant 鉴权且 `no-store` 的后端接口传输。

浏览器成功显示的像素始终可能被保存或截图，因此安全边界是“不向浏览器传输原图”，而不是试图隐藏一个已经发出的网络请求。

不得在对象 key、文件元数据、日志或审计摘要中保存密码、令牌或其他秘密。

## 审计与日志

交易、库存、商品、展会和管理员写操作记录操作者、Tenant、实体 ID、动作与必要摘要。批量删除同时记录批次摘要和每笔交易的删除记录。应用日志使用 `traceId` 关联请求，并避免记录 JWT、Cookie、密码和对象存储密钥。

## 生产检查清单

- 使用独立数据库账号并限制权限。
- Secret 只通过平台 Secret 管理，不写入镜像或仓库。
- 数据库和对象存储启用备份与恢复演练。
- 健康检查不暴露敏感配置。
- 定期审查管理员账号、Refresh Token 异常和跨 Tenant 拒绝记录。
